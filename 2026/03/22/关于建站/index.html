建立个人博客网站分为静态和动态

静态需要在本地部署，然后托管至github等平台。 本地需要安装Git、Node.js，本站采用hexo为模板，安装hexo后，选用主题。

除了hexo，还有hugo。

动态即包含数据库，可实时在线编辑。 主流博客框架有：Typecho（优点轻量）、Halo、Wordperss（使用人数最多）

涉及到的概念：

Node.js： 是一个 JavaScript 运行时环境，它让你可以在 服务器端 运行 JavaScript 代码。 版本管理工具：nvm、fnm、docker；包管理工具：npm、yarn、pnpm。

Jekyll： 是一个基于 Ruby 的静态站点生成器，由 GitHub 联合创始人 Tom Preston-Werner 开发，并于 2008 年发布。它最著名的特性是 与 GitHub Pages 原生集成——你只需将源代码推送到 GitHub 仓库，GitHub 就会自动用 Jekyll 生成并托管网站，无需本地构建。

本地构建：指在自己的计算机上运行静态站点生成器（如 Jekyll、Hexo、Hugo 等），将源代码（Markdown 文章、模板、配置文件等）编译成最终可部署的静态文件（HTML、CSS、JavaScript）的过程。

ESlint：是一个 JavaScript 代码检查工具（linter），用于发现代码中的问题、统一编码风格，并在开发过程中提前避免潜在错误。它诞生于 2013 年，是目前 JavaScript 生态中最主流的静态分析工具，被广泛应用于前端、Node.js 以及 TypeScript 项目中。

**原理：**ESLint 通过 静态分析 源码（不运行代码），基于一套可插拔的规则来检查代码。其工作流程大致如下：

  1. 解析：使用解析器（默认 Espree，也可配置为 @babel/eslint-parser 或 @typescript-eslint/parser）将代码转换为抽象语法树（AST）。
  2. 规则匹配：遍历 AST，对每个节点应用配置的规则，规则会判断是否符合预期。
  3. 报告：收集违反规则的信息，输出错误或警告。

Experience

本地建站步骤还是比较繁琐，安装问hexo后，选用相关主题，在config.yml文件的theme后面更改为主题的名字。

配置文件分为：

  • Hexo 配置文件 hexo-theme-keep-starter/_config.yml
  • Keep 主题配置文件 hexo-theme-keep-starter/source/_data/keep.yml

内容、文章撰写在source/_posts中，keep.yml可客制化网站页面，如添加muen等。

托管：

在github上新建仓库（repository）

git init：效果：创建一个名为 .git 的隐藏文件夹，其中包含 Git 所需的所有元数据（如对象库、引用、配置等）。从此，该目录就被 Git 管理，可以记录文件变更历史。

git branch -M main:-M 是 --move --force 的缩写，强制重命名。Git 默认的初始分支名通常是 master（旧版）或 main（新版），此命令将当前分支（初始为 master）改名为 main，以匹配 GitHub 等平台创建仓库时的默认主分支名，避免后续推送时的名称不一致。

**remote add：**添加远程仓库关联。origin：是远程仓库的默认名称（约定俗成）。

git push -u origin main: -u（即 –set-upstream）：将本地的 main 分支与远程的 main 分支关联起来，以后只需运行 git push 或 git pull 即可自动与这个远程分支同步。origin main：推送到名为 origin 的远程仓库的 main 分支.

**注意：**如果是通过clone他人仓库，首先要git remote remove origin，清除旧的远程地址，然后再通过ssh远程连接自己的仓库。

配置 GitHub SSH 密钥认证

用于实现本地与 GitHub 之间的安全连接，避免每次推送或拉取代码时输入用户名和密码，验证本地私钥和github上公钥匹配后，后续通过ssh协议进行push，pull。

ssh-keygen -t ed25519 -C "你的GitHub邮箱"

作用：生成一对 SSH 密钥（公钥和私钥），用于身份验证。

  • ssh-keygen：SSH 密钥生成工具。
  • -t ed25519：指定密钥类型为 ed25519。这是目前推荐的高安全、高性能加密算法，相比 RSA 更短且更安全。
  • -C "你的GitHub邮箱"：添加注释，通常填写你的 GitHub 关联邮箱，用于标识密钥的归属（不是必需的，但便于管理）。
  • 执行过程：命令会提示你选择保存路径（默认 ~/.ssh/id_ed25519）和设置密码短语（passphrase，可选，用于额外保护私钥）。

cat ~/.ssh/id_ed25519.pub | clip

作用：将生成的公钥内容复制到系统剪贴板，方便粘贴到 GitHub 设置中。

  • cat ~/.ssh/id_ed25519.pub：读取公钥文件的内容并输出到终端。
  • |（管道）：将前一个命令的输出传递给后一个命令。
  • clip：Windows 系统的剪贴板命令（macOS 上使用 pbcopy，Linux 上使用 xclip 或类似工具）。
  • 效果：公钥内容（如 ssh-ed25519 AAAAC3... 你的GitHub邮箱）被复制到剪贴板，你可以直接粘贴到 GitHub 的 SSH 密钥添加页面。

ssh -T git@github.com

作用：测试与 GitHub 的 SSH 连接是否配置成功。

  • ssh：SSH 客户端，用于建立安全连接。
  • -T：禁止分配伪终端，仅用于测试连接（不执行远程命令）。
  • git@github.com：GitHub 的 SSH 服务地址（用户名固定为 git）。

Git配置

Git 要求每次提交都附带作者姓名和邮箱，否则无法完成提交。即使你不设置，Git 也会尝试从系统环境变量中读取（如 GIT_AUTHOR_NAME），如果都没有，就会报错提示你需要配置。

Hexo部署推送

npm install Node.js 的包管理工具，用于安装依赖包。
hexo-deployer-git 要安装的包名，这是一个 Hexo 插件，用于将 Hexo 生成的静态网站通过 Git 推送到远程仓库（如 GitHub Pages、Gitee Pages 等）。
--save 将安装的包添加到 package.json 文件的 dependencies 字段中。注意：在 npm 5.0.0 及以上版本中，npm install <包名> 默认就会保存，但加上 --save 是更明确的写法（也可用 -S）。
  • 功能：为 Hexo 提供 git 部署方式。在 Hexo 的配置文件 _config.yml 中配置好远程仓库地址、分支等信息后，执行 hexo deploy（或 hexo d）时，插件会自动将生成的静态文件（public/ 目录）推送到指定的 Git 仓库。
  • 典型场景：部署 Hexo 博客到 GitHub Pages 时，通过此插件可以一键推送，无需手动复制文件。

Github Action

作用：push后（更改源码后，如.md文章），自动构建，发布网站。 流程： GitHub 开一个临时虚拟机，然后拉代码 → 装 Node → 装依赖 → 构建 → 上传产物 → 部署到 GitHub Pages。
